# Effect-scoped passkey approvals

Shelved. Do not start without an owner decision. This is not a walking question while Rack phase 4 is the authorized slice.

Source: a 2026-09-04 coordination note, subject "Suggestion: effect-scoped approvals with passkeys." It was an FYI. Preserved constraints:

- A fresh passkey assertion would bind the action (argv, cwd, target, expiry, and executable bytes where practical), not a displayed sentence.
- Replay, expiry, the wrong relying party, a hidden command substitution, or a redirect that escapes through `..` or a symlink must fail.
- An unrecognized external program gets containment rather than implicit broad authority.
- Replacing Rash, the verifier, or the privileged executor still bypasses the design. It is not a hard boundary by itself.

Threat-model entry T-POL-07 already names approval fatigue. No implementation is authorized from this note.
